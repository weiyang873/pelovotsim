**版本**：v1，2026-07-14
**分支**：`research/experiments-20260714`。独立脚本，不起 server，不动 main，**不碰 Dockerfile/package.json/package-lock.json 的工作区改动**。
**前置**：full_game_all_personas_v1（7/7 完成）确认：认知地图分化"方向"（选格/VP/选卡/定价方向 7 条轨迹可辨），但不分化"执行质量"——7 人全部正确执行 成本÷(1-target_gm) 的定价算术、全部卡价格于 WTPadj 之下，6/7 盈利（86%）vs 真人 37.5%。既有结论（四层结构）：执行层对 prompt/地图路线不可达；日志已预埋 B 路线——用计算性干预（锚注入/信息截断/停止规则）制造执行缺陷。C2 已验证锚注入可行（锚移 8,736）；P2 已建信息截断机制。本轮是 B 路线在完整游戏链上的第一次实跑。

**核心设计原则：缺陷从地图盲区推导，类型必须是计算性的（被推理"用掉"的操作数），不是描述性的（被读到的形容词）**——后者已四轮验证无效。

**假设声明（如有误直接改）**：
- 只用 2 个已冻结 persona（草根老板/二代接班人），每人 2 条链：D 条件（注入缺陷）+ N 条件（无缺陷，即 full_game 装置原样），共 **4 条完整 playthrough**。N 条件不复用 full_game v1 的旧链——锦囊随机抽取导致不可比，本轮 4 条链内**同一 persona 的 D/N 两条链锁定使用相同的锦囊抽取结果**（消掉抽卡运气这个混杂）。
- 流程完全复用 `full_game_all_personas.js`（R0→R1 选格→Coach→R2 动态画像→D3'/D4/D5→真实结算），只在 D 条件的指定环节加干预层，其余一字不改。
- 缺陷参数（截断哪类信息、锚偏多少）本轮取值是**试探性的首选值**，写死并记入 meta；它们不是最终校准值——正式校准要对真人 trace（BQ 数据），那是后续工作。

## 0. 目的

检验：在 harness 层注入从地图盲区推导出的计算性缺陷，能否让 persona 的决策以"该 persona 该有的方式"变差——即缺陷的扭曲方向与盲区一致、且在无缺陷对照下不出现。这是"让 AI 会输"的第一次机制验证，不是校准，不是复现真人盈利率。

## 1. 缺陷设计（每人一种，从盲区推导）

### 草根老板 → 视野截断（信息侧缺陷）
盲区：现金/试单隧道，看不见长期价值信号。
实现：D3' 环节，动态画像 summary 送入 prompt **之前**，经确定性过滤器删除其中的"长期价值类"句子——判定用关键词表（品牌、口碑、长期、复购、忠诚、生态、生命周期价值、溢价意愿等，Codex 结合 personaGenerator 实际输出词汇定表，写入 meta），命中即整句删除。R1 选格与 Coach 环节不动（截断只作用于证据读取，对应"读材料时只看见眼前回款"）。删除的句子逐条落盘（审计需要）。
预期扭曲方向：漏掉支撑更高配置/更高定价的需求信号 → 配置更低、定价更保守、或错判市场空间——且理由文本中不出现被删信息的痕迹。

### 二代接班人 → 锚偏置（数字侧缺陷）
盲区：品质/背书执念，系统性高估客户支付意愿。
实现：D5 环节，prompt 中注入的 `WTPadj_scaled` 数值替换为 **真实值 × 1.4**（+40% 上偏，量级参考 C2 锚移验证的可行范围；仅改 prompt 中呈现给 persona 的数字，真实结算 `calculate()` 用真实值——缺陷在"他以为"，市场按"实际是"结账）。D4 不动。
预期扭曲方向：定价向虚高锚靠拢 → 实际 Q 被真实需求曲线惩罚 → 利润受损，且定价理由中引用了这个虚高数字。

**两种缺陷都是操作数级干预**（删掉的句子、改掉的数字），不在 prompt 里写任何"你倾向于忽略长期价值"之类的自我描述。

## 2. 矩阵

2 persona × {D 缺陷, N 无缺陷} × 1 次 = **4 条完整链**。同一 persona 的 D/N 使用相同锦囊抽取（实现方式：先抽一次，两条链共用；记入 meta）。

## 3. 判决指标（N=1/格，全部描述性）

1. **缺陷是否被"用掉"**（主判决）：
   - 草根 D 链：被删句子清单 + D3' 证据/市场判断中是否确实缺失对应主题（与 N 链对照）；下游配置/定价是否随之改变
   - 二代 D 链：D5 定价与理由是否引用虚高锚（对照 N 链定价）；`他以为的WTP` vs `真实WTP` vs `最终定价` 三个数并排呈现
2. **扭曲方向与盲区的一致性**：变化方向是否符合第 1 节的预期方向（如实记录，不符也照实写——方向不符本身是重要结果）
3. **经济后果**：4 条链的 Q/profit 并排；D 链是否比同 persona 的 N 链差、差在哪个环节（Q 被杀 / 成本失衡 / 市场错判）
4. **语言层检查**：D 链的理由文本是否出现"我被截断了/这个数字可能不准"之类的元认知泄漏（出现则说明干预被模型察觉，机制打折，如实记录）
5. 一句话观察：计算性缺陷注入是否产生了"方向正确的变差"——这是 B 路线可行性的第一个数据点

## 4. 验收

1. 4/4 链完成全流程，D4 兼容性全过，数值无 NaN/null
2. 草根 D 链的删除句子清单完整落盘；二代 D 链的真实/虚高 WTP 两个值都记入 jsonl
3. 四件套产物（summary/raw_samples/jsonl/meta），格式对齐 full_game v1；meta 记录缺陷参数（关键词表、1.4 倍率）、共用锦囊抽取结果、全部 sha256
4. summary 中明确标注：缺陷参数为试探值未经真人 trace 校准，结果为机制验证不是保真度声明
