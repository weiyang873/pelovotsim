## Part 1：信息集对齐规范（INFO-SET RULE）

### 1.0 总原则

**AI persona 每个决策环节可见的信息 = 真人学生该环节 UI 上可见的信息。** 不多不少。判据："真人也面对的信息是游戏，真人不面对的信息是泄漏。"

**数字采用白名单制**：prompt 中允许出现的数字只有 1.1 节白名单里逐项列出的；任何未列入的数字（含比例、系数、公式）一律禁止。拿不准某字段真人是否可见时，读真实前端（`client/` 与 R2 页面代码）确认渲染；读不出来停机问 WY，不猜。

### 1.1 数字白名单（WY 已逐项确认）

| # | 数字 | 环节 | 依据 |
|---|---|---|---|
| 1 | 定价提交边界 1000-6000（不写步长/默认价） | D5 | 真人面对的是滑块边界；prompt 需声明这不是建议价、合理价、市场价或锚定价格 |
| 2 | 每维度至少 1 张、总数至少 6 张 | D4 | 游戏规则，界面强制 |
| 3 | tier 三档（low/mid/high 的存在） | D4 | 真人可见档位 |
| 4 | 12 格结构（3 人群 × 2 渠道 × 2 策略） | R1 | 选格界面本身 |
| 5 | persona 地图内数字（"亏了19万"等） | 全程 | persona 自身记忆，非环境信息 |
| 6 | 画像 summary 内数字（如有） | D3 | 玩家可读访谈素材，真人同样读到 |

**边界项（Codex 对前端核实后归类，核实结果记入 meta）**：
- R1 结算定性档位（Margin Headroom 档位、Market Space Tier 的 S/M/L）——以 R1 结果页实际渲染字样为准
- D4 卡片 covers 标签——以 R2 选卡页实际渲染为准（对齐 T2）
- 锦囊玩家可见文案自带数字——文案里本来有就保留，属游戏内容

### 1.2 明确禁止清单（v1 泄漏项全量，v2 一律移除）

target_gm 数值（0.65/0.595）、target_gm_rule 公式、WTPref_scaled、WTPadj_scaled、wtp_multiplier、rho_C、jinang match_strength 精确小数（改定性：高度契合/部分契合/契合度有限）、effect_at_full_match 明细、每张卡的 dCOGS/risk/sub_lift/load/nre 数值、capacity_points、budget_cap 公式与乘数表、全部 z_penalty/risk_add 惩罚值、兼容性规则机器可读参数（真人可见的文字冲突提示保留，以前端渲染为准）。

**特别说明 target\_gm**：真人在 R2 界面没有这个数字，故 D5 不注入。persona 的栈里如果 R1/Coach 阶段自己形成过毛利相关的表述（自己说过的话），作为栈记忆保留——"他记得自己的战略"合法，"环境递给他一个精确数字"不合法。

### 1.3 指令与 schema 纪律

- 不在任务指令里规定任何数字的用法（"检验可达性""必须覆盖成本"等）。
- 输出 JSON 只含决策本身字段（选择、理由、约束栈），不加"解释你如何使用了某参数"的观测字段（v1 的 target_gm_usage 属此类，删）。

### 1.4 校验要求（防回归）

脚本内置 `assertInfoSet(promptText, stage)`：对每环节最终 prompt 跑 1.2 禁止清单的关键词/模式扫描 + **通用数字扫描**（prompt 中出现的每个数字必须匹配白名单模式，未匹配即抛错终止）。此函数随脚本入库，后续实验脚本 require 复用。

### 1.5 呈现结构对齐（工作记忆规则，2026-08-15 增补，WY 确认）

**内容对齐不等于信息集对齐。LLM 的默认工作记忆是超人的：真人"看得到但拿不住"的信息，一旦在 prompt 里同屏拼接，效果等同泄漏。**

- **分页的东西不能拼页**：真人 UI 上分属不同页面/环节的信息（如客户调研页的需求标签 vs 选卡页的卡片列表），不得合并进同一条 prompt。真人靠翻页+记忆桥接，模型必须同样靠上文记忆和讨论转述桥接。
- **靠记忆传导的东西不能重印**：早期环节展示过的信息（调研摘录、痛点明细、需求标签），在后续环节的 prompt 里不得重印。它们已经在 transcript/上文里出现过，"记不记得住、转述得准不准"本身就是被仿真的行为。
- **判据**：如果两块信息在真人流程里从未同屏出现，而 prompt 把它们并排递给模型，即视为呈现结构泄漏——即使每一块单独都在白名单内。

**案例（2026-08-15，team R2）**：D4 个人选卡 prompt 同屏拼接了"需求标签：…"（调研页内容）与每张卡"覆盖=…"（选卡页内容），构成现成匹配表；叠加分工机制（每人只管 1-2 个维度、约 4 张卡，小视野×对照表=满分并集），coverCore 稳定 0.66-0.76，而真人 <0.6、902 基准 0.62、solo 0.60（solo 同款泄漏因一人面对全部 23 张卡而被认知规模稀释）。移除重印（commit 0d4de833）后 coverCore 降至 0.66 且首次出现 0.48-0.58 的真实失误带。

### 1.5 已知代价（如实记录）

去掉精确成本/WTP 后，persona 的成本与支付意愿判断只能来自卡片文字描述、画像素材与自身经验——可能出现真人式误估（这正是目的）；也可能出现极端配置。**结算仍用真实参数**：引擎照常按 dCOGS/sub_lift/惩罚公式记账，玩家看不见账本但账本照常记——这就是真人的处境。
