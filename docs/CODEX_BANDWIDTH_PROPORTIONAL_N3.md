## 1. 修正：带宽比例制

`bandwidth_layer.js` 的预算公式从绝对数改为占 `map_total` 的比例：

```
B = max( floor(R_min × map_total),
         floor((R0 − r × stack_len) × map_total) )
R0 = 0.40      # 初始可见比例
r  = 0.06      # 每步递减比例
R_min = 0.16   # 下限比例
```

对 50 条地图：R1=20 条、D5=8 条——**与旧公式完全一致**（冻结组的历史结果口径不变）；对 25 条地图：R1=10 条、D5=4 条（旧口径下是 20/8）。取整用 floor，任何情况下 B≥1。审计字段增加 `map_total`、`ratio_visible`（=B/map_total），落选记录格式不变。

## 3. 判决指标（第一次可以报均值的一轮）

1. **盈利率与利润：按条件报均值±区间**（7人×3 = 21 链/条件）。F 盈利率均值 vs B 盈利率均值——三级阶梯的"闭卷→闭卷+带宽"一段能否以均值形式站住
2. **格子稳定性矩阵**：每人 F×3 与 B×3 的格子选择列表——F 内部稳的人里，B 是否系统性漂移（现在 AI 生成组被真实约束了，漂移归因第一次干净）
3. **可见比例均等性验证**：审计确认两组 `ratio_visible` 逐步相等（40%→16%），混杂消除的直接证据
4. **上轮"复现表"逐行重验**：草根 B 提价（旧证据 2/2）、二代格子漂移（2/2）、体制 B 改善（2/2）、B 总利润<F（2/2）、B 定价整体偏高（6/7）——每行在 N=3 下存活与否
5. **PM rank-9 型事件的发生率**：落选清单中 rank=B+1（差一名落榜）且该条目在同 persona 任一 F 链被引用的事件计数——"调用失败"从存在性证据升级为发生率的第一个读数
6. 局限声明写入 summary：N=3 仍小、锦囊单套未随机化、solo 装置、温度 0.55
